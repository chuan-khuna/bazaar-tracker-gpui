# Implementation documents

How this project is built. Domain terms are defined in [GLOSSARY.md](../../GLOSSARY.md).

- [Developer setup](README.html) — for a new developer: what is in the workspace (the three crates and the app), the prerequisites (Windows, Rust 1.92+, just, the game, the WebView2 Runtime), the first build and why dependencies build at `opt-level = 2`, `just build` and `just app`, where the data folder is and what it holds (one writer at a time), `just spike`, `just snapshot` and `just track` against the live game, `just art` and `just shop-odds`, the tests, and common errors.
- [Architecture](architecture.md) — the repo and crate layout, layering rules, data folders and theme roles.
- [Modules](modules.md) — what each module in `crates/` and `src/` does, and how an Event flows from the game to the window.
- [Data folder](data-folder.md) — where the app keeps its data, how to point a release build at the repo with `BAZAAR_TRACKER_DATA_DIR`, and the `art/` folder's layout.
- [Memory reading](memory-reading.md) — how the app reads the running game. `unityspy-rs`: read-only process access (`PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION`, exe `FileVersion` to Unity version), module and PE export lookup, the `mono_get_root_domain` check and assembly walk, the offset tables per Unity line (2021/2022 verified, 6000+ unverified, anything else an error), the class cache, fields up the parent chain, statics through the vtable, values by type code, BCL `List`/`Dictionary`/`HashSet`/`Nullable`, the `Memory` trait and `mono::testing`. `bazaar-tracker`: the `GameMemory` contract (`Ok(None)`, `Ok(Some)`, `Err`), `BazaarMemory`'s attach, reconnect and detach rules (500 ms ticks, optional classes retried every 5 s, detach after 5 failed board reads), the game classes and singletons behind each read, sorting cards into Board, Stash and skills, the rank scan, `Snapshot` and its parts, `FakeMemory`, `just spike` and `just snapshot`, and what to do after a game update.
- [Player.log](player-log.md) — where the game's log is (`LocalLow\Tempo Storm\The Bazaar`, the `log_path` setting, `just track --log`), following it (500 ms polls from the end, a missing file waited for, truncation and replacement caught by a 256-byte tail signature, at most 16 MiB a pass, whole lines only), and parsing: the dropped timestamp, the substring guards before the regexes, and each `LogLine` variant with real example lines and near misses.
- [Run state machine](run-state-machine.md) — how `run/` and `tracker/` turn log lines and memory reads into Events: `Run`, `Outcome`, every `EventKind` (trigger, fields, JSON with its `type` tag), the `RunMachine` model (fed lines and time, drained by `take_outputs`, `Output::Event` and `Rebound`, `Clock`, generation-counter timers), every delay (500 ms settle, 350 ms combat capture, 1200 ms combat-end retry, the 4 s ranked rating wait, the hero wait), the Run lifecycle (`local-` ids, rebinding, end triggers and outcomes), options, selection, sells and rerolls, how a combat's result is decided, the `Tracker` service (four threads, the ordered save queue retrying 1 s to 30 s, live Snapshot polling, every `Notice`), `just track`, and the whole-log replay tests.
- [history.db](history-db.md) — the SQLite file: WAL with a writer and a `query_only` reader, every table, column and index (`runs`, `events`, `shop_odds`, `item_odds`, `tracked_items`, `hidden_items`), migrations 1–6, the `user_version` rules (older migrated, newer refused), how saving an Event updates its Run's summary, rebinding a Run's id (rename or merge), deletion by cascade, upload status codes, times in Unix ms, and example `sqlite3 -readonly` queries for inspecting it.
- [Bazaar DB](bazaar-db.md) — reading bazaardb.gg in `crates/bazaardb` and the features built on it: the honest `GET` and how it tells a refusal from a Cloudflare challenge, why Turnstile needs a real browser view, `/api/shop-odds` and the built-in day 1–16 defaults, `/api/item-odds`, the `webview` feature (`script.js` capturing replies, the `#bazaar-tracker-find=<name>` search, the borderless popup moved by `WebView::place`); the Shop odds column beside the Economy and the Shop odds Widget (Refresh, Import JSON…), the odds button on a hovered item with its 20 s fallback, `accept`, the ITEM ODDS block at an encounter choice (`watched`, `choice_groups`, folding, ✕ to hide), the Tracked items pop-up, loading many items from Settings (random 0.5–4 s wait, 20 s skip), the debug panel, the history.db tables, and `just shop-odds`.
- [Upload](upload.md) — uploading saved Events to Bazaar DB (built, never started by the app, and to be removed: see the 2026-11-02 record): which Events are sendable, batches of 200 Events or about 2 MB gzipped, the `Transport` trait and its 110 s timeout, what each server answer does (halving on 413 or timeout), the 15 s to 1 h backoff, the secret key in the Windows Credential Manager, and `events.upload_status`.
- [gpui app](gpui-app.md) — the window app in `src/`: running it (no command-line options, only `BAZAAR_TRACKER_DATA_DIR`), startup in `main.rs` (the per-folder single-instance lock and focusing the first window, logging, settings, the service, the window's sizes), how notices flow into `Status`, `LiveState`, the log panel and `Session`, each island and its resize range (title bar, runs sidebar with Widgets, Live island, Run island with header, day buttons, Economy chart and Events filters, board tiles, detail island, log panel with its 2,000-row buffer, status bar), the ☰ menu and command palette with all nine commands, keyboard shortcuts, the theme picker and the ten themes with their 29 roles, the Settings overlay, every `settings.toml` key with its default and range, `logs/tracker.log` (1 MiB rotation, 3 backups), time formats (ADR 0001), and the gpui dependencies.
- [Card catalog and art](card-catalog-and-art.md) — how card ids become names and pictures: `CardCatalog` (fields, `Common` for neutral, `GameData.db` read from a copy before `cards.json`, newest of four paths wins, empty on failure, loaded off-thread), finding the install folder (`game_dir`, Steam libraries, then the running game), and the art extractor (plan, skip existing or `--force`, parallel bundle workers, `manifest.json`), the Addressables `catalog.bin`, UnityFS bundles (LZ4; LZMA and encryption refused), serialized files and type trees, Texture2D decoding, WebP output (512 px, quality 82, atomic writes), `just art`, the app's `shell/art.rs`, and how the board draws the art.
