1. What's in the repo

One Cargo workspace: the app at the root and three library crates in crates/. Each layer uses only those above it (see Architecture):

unityspy-rs

crates/unityspy-rs/: reads a running Unity (Mono) game's memory, read-only. Knows nothing about The Bazaar.

bazaar-tracker

crates/bazaar-tracker/: follows Player.log, reads the game, runs the Run state machine, saves history.db; also the card catalog, card art and upload. No UI.

bazaardb

crates/bazaardb/: reads Bazaar DB's Shop odds and item odds, through a plain GET or an Edge WebView2 view.

The app

src/: the gpui window. It starts the tracker service and draws what it saves.

Every command lives in the justfile at the repo root. Run just to list them. Each recipe is a plain cargo command, so just is optional.

3. First setup

git clone <repo-url> bazaar-tracker-gpui
cd bazaar-tracker-gpui
just test        # cargo test --workspace: every crate, no game needed
just run         # debug build, opens the window; data in .bazaar-tracker/

The first build compiles gpui and its dependencies, which takes several minutes. Dependencies are built at opt-level = 2 even in debug ([profile.dev.package."*"] in Cargo.toml), or the window lags while scrolling; the app's own code stays quick to rebuild.

For a build you play with every day:

just build       # cargo build --release, into target/release/ (alias: just release)
just app         # starts that build with its data in .bazaar-tracker/, without rebuilding

A second launch with the same data folder brings the first window forward and exits.

4. Where the data lives

BuildFolder
Debug (just run)<repo>/.bazaar-tracker/ (gitignored)
Release%APPDATA%\BazaarTracker\
Either, overriddenBAZAAR_TRACKER_DATA_DIR (just app sets it to the repo's folder)
 
.bazaar-tracker/
├── settings.toml        # theme, log_path, game_dir, run_sync, card_size, window layout
├── history.db           # Runs, Events, saved Shop odds and item odds, tracked and hidden items
├── logs/tracker.log     # tracing output, rotated by size
└── art/                 # card images from your own install (just art); never commit them
  • A missing settings.toml is written with defaults. One that can't be read or parsed means defaults in memory, and the file is left alone.
  • history.db is migrated forward when it is older than the app, and refused when it is newer. See history.db.
  • The Bazaar DB secret key is in the Windows credential store, under a separate entry in debug builds. Uploading is built but off: run_sync exists in settings.toml, but nothing starts the uploader yet. See Upload.

One writer at a time. The app, just track, and debug and release builds pointed at the same folder all write the same history.db. Run one of them at a time.

Moving the folder and setting the variable by hand: Data folder.

5. Checking it against the game

These need The Bazaar running. Start with just spike after every game update: memory reading depends on the game's Unity version and class layout.

CommandWhat it does
just spikeAttaches, prints the Unity version, the offset table, the loaded assemblies and the fields of the game classes the tracker reads, then the BoardManager singleton and the entity count.
just snapshotPrints one Snapshot: run id, hero, run state, stats, Board, Stash, skills, opponent, rank and last combat. -- --watch prints one every poll.
just trackThe whole tracker without a window: follows the game, saves to history.db and prints each Event. -- --log <path> follows another Player.log. Ctrl+C stops it.

The tracker only reads the game's memory, with PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION. It never writes to it and never needs admin rights. How it works: Memory reading, Player.log, Run state machine.

6. Card art and odds

Both are optional: the app works without them.

just art                                    # find the game in Steam, write .bazaar-tracker/art/
just art --game "H:\SteamLibrary\steamapps\common\The Bazaar"
just art --force                            # redraw every image
just shop-odds                              # ask Bazaar DB's API (usually refused)
just shop-odds shop-odds.json --json        # read an answer saved from a browser

The first just art takes about 30 s and writes about 65 MB; later runs write only what is missing. The app does the same from Settings → Card art → Extract art. The art is Tempo Storm's, for local use only. See Card catalog and art.

Bazaar DB's API wants a Cloudflare Turnstile token, so the app reads Shop odds and item odds through Bazaar DB's own page in a web view rather than a plain request. See Bazaar DB.

7. Running the tests

just test                                # cargo test --workspace
cargo test -p bazaar-tracker             # one crate
cargo test -p bazaar-tracker --tests     # the crate's tests, with the whole-log replays

A plain cargo test at the root tests only the app, not the crates. Tests sit beside the code as <name>_tests.rs. None of them need the game: mono::testing feeds byte buffers to unityspy-rs, FakeMemory and ManualClock drive the Run state machine, and crates/bazaar-tracker/tests/ replays the recorded logs in tests/fixtures/logs/.

8. When something goes wrong

  • The status bar never says attached. Start the game, then run just spike. "no Mono offsets for Unity version …" means a game update moved to a Unity version with no offset table yet; the tables are in crates/unityspy-rs/src/mono/offsets.rs.
  • No Events appear. The tracker follows the game's Player.log. If yours is somewhere else, set log_path in settings.toml; the log panel's pinned details show the path it uses.
  • Cards show no names or no art. The game folder wasn't found. Set game_dir in settings.toml, or pass --game to just art.
  • "history.db has schema version N, but this app only understands up to M". A newer build migrated the file. Use that build, or point this one at another folder with BAZAAR_TRACKER_DATA_DIR.
  • The window lags in a debug build. Check that [profile.dev.package."*"] with opt-level = 2 is still in Cargo.toml, or use just build and just app.
  • Odds never load. Bazaar DB's page needs the WebView2 Runtime and a passed Cloudflare check. Open the Bazaar DB panel to see the page and the replies it got.
