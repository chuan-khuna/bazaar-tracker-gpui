1. About this manual

This manual tells you how to build and start Bazaar Tracker, what each part of the window shows, how the app gets its data from the game, and where it keeps that data on your computer.

The terms Run, Live run, Event, Snapshot, Board, Stash, Shop odds and Widget have the meanings given in GLOSSARY.md. For the full detail of each part, see the documents in Related documents.

NoteWindows is the main platform. The code also tracks the game on macOS, and this manual gives the macOS paths where they are different.

2. What the app does

Bazaar Tracker runs next to The Bazaar while you play. It records each Run: the options the game offered, what you picked, bought and sold, your Board at each step, and the result of each fight. You can look back at any Run, day or Event later.

The app only reads the game. It does not change the game, and it does not need admin rights. Your runs stay on your computer.

3. Before you start

Make sure that these tools are on your computer:

ToolVersion testedWhy you need it
Windows11 (10 also works)Memory reading, the single-instance lock, the credential store and the Bazaar DB web view.
Rust (cargo)1.99.1To build the app. The code uses edition 2024, so you need 1.92 or newer. To update, run rustup update stable.
just1.46.0To run the recipes. It is optional: each recipe is one plain cargo command.
The Bazaar (Steam)currentFor tracking, card names and card art. The window opens without it.

You do not need to install SQLite. The app builds its own copy (the bundled feature of rusqlite).

On macOS, Cargo signs each binary before it runs it (apps/tracker/macos/run.sh and apps/tracker/macos/sign.sh). The signature gives the binary permission to read the game's memory. You must have Apple's Command Line Tools.

4. Start the app

4.1 First start

  1. Get the code: 
    git clone <repo-url> bazaar-tracker-gpui
cd bazaar-tracker-gpui
  2. Run the tests. They do not need the game. 
    just tracker test
  3. Build and start a debug build: 
    just tracker run

    Result: the window opens. The status bar shows Waiting for the game.

  4. Start The Bazaar.

    Result: the status bar shows Tracking with a green dot. When you start a Run, it shows in the sidebar with a LIVE badge.

The first build compiles gpui and all its dependencies, so it takes several minutes. Later builds are fast. Dependencies are built at opt-level = 2 even in a debug build ([profile.dev.package."*"] in the root Cargo.toml), because without this the window lags when you scroll.

A debug build keeps its data in .bazaar-tracker/ in the repo. See Where the data folder is.

4.2 The build for daily use

A release build is faster and smaller. Use it when you play.

  1. Build it once, and again after each change you pull: 
    just tracker build
  2. Start it: 
    just tracker start

    Result: target\release\bazaar-tracker-gpui.exe starts with BAZAAR_TRACKER_DATA_DIR set to the repo's .bazaar-tracker/. The release build and the debug build then use the same history and the same settings.

just tracker start does not build. If you changed the code, run just tracker build first.

If you start the .exe yourself (for example from Explorer), it uses %APPDATA%\BazaarTracker\, not the repo folder. To change this, set the variable. See Data folder.

4.3 App commands

Run just to see all recipes. These are the ones for the app:

CommandWhat it doesPlain cargo
just tracker runBuilds and starts a debug build. Data goes in .bazaar-tracker/.cargo run -p bazaar-tracker-gpui
just tracker buildBuilds a release build into target/release/. just tracker release does the same.cargo build --release -p bazaar-tracker-gpui
just tracker startStarts the release build, with its data in .bazaar-tracker/. Does not build.the .exe with BAZAAR_TRACKER_DATA_DIR set
just tracker testRuns the tests of every crate.cargo test --workspace

just tracker cleanDeletes the build output in target/. The next build starts from zero.cargo clean

The app reads no command-line options. Its only outside input is the BAZAAR_TRACKER_DATA_DIR environment variable.

4.4 Stop the app

Close the window, or press Ctrl+Q. The app stops its background threads before it exits.

If you start the app a second time with the same data folder, the second copy does not open a window. It brings the first window to the front and exits.

6. How the app works

6.1 Two sources

The tracker uses two sources together. Each one gives what the other cannot.

SourceWhat it givesHow the app reads it
Player.logWhen something happens: a Run starts or ends, options are offered, you pick or sell, a fight starts.It follows the file as it grows, from the end, every 500 ms.
Game memoryWhat is there: the real run id, your Board, Stash and skills, gold and health, the shop's items, the opponent, rank and combat results.It attaches to TheBazaar read-only (PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION) and reads the game's Mono objects.

The log lines are the triggers. The memory gives the data. The run state machine puts the two together and makes Events.

Where the game keeps Player.log:

  • Windows: %USERPROFILE%\AppData\LocalLow\Tempo Storm\The Bazaar\Player.log
  • macOS: ~/Library/Logs/Tempo Storm/The Bazaar/Player.log

If your log is in a different place, set log_path in settings.toml.

6.2 Data flow

flowchart LR
  log[["Player.log"]] --> follow["log::follow and log::parse"]
  game["TheBazaar process"] --> spy["unityspy-rs: read-only memory"]
  spy --> mem["memory: GameMemory"]
  follow --> machine["run::RunMachine"]
  mem --> machine
  machine -->|"Events"| store[("history.db")]
  machine -->|"Notices"| bridge["tracking::service"]
  bridge --> app["TrackerApp: the window"]
  store -->|"reads"| app
  catalog[["GameData.db: card names"]] --> app
  art[["art/: card images"]] --> app
  bazaardb["bazaardb.gg in a web view"] -->|"Shop odds, item odds"| store

The tracker code (crates/bazaar-tracker) has no UI. The window (apps/tracker/src/) only draws what the tracker reports and what history.db holds.

6.3 One Event, from the game to the window

sequenceDiagram
  participant G as The Bazaar
  participant L as tracker-log thread
  participant M as tracker-machine thread
  participant D as history.db
  participant W as Window
  G->>G: writes "State changed ... to [ChoiceState]" to Player.log
  L->>L: reads the new line
  L->>M: the line
  M->>M: parses it, starts a 500 ms settle timer
  M->>G: reads the options and a Snapshot from memory
  M->>M: makes an OptionsPresented Event
  M->>D: saves the Event and updates its Run
  M->>W: Notice EventSaved
  W->>D: reads that Run again
  W->>W: redraws the sidebar, Events table and log

The machine waits 500 ms after the log line before it reads the memory, because the game needs a short time to put the new state in memory. Other Events use other delays. For example, the app waits up to 4 s for the ranked rating after a Run ends.

6.4 What happens at startup

apps/tracker/src/main.rs does these steps in this order:

  1. Data folder. The app finds the data folder and makes it if it is missing. If it cannot make it, the app stops with exit code 1.
  2. Single-instance lock. The app takes a lock that has the data folder's name in it. If another copy has the lock, this copy brings that window to the front and exits.
  3. Logging. The app opens logs/tracker.log and writes the data folder's path to it.
  4. Settings. The app reads settings.toml. If the file is bad, the app uses the defaults and shows why in the status bar.
  5. Tracker service. The app opens history.db (and updates its schema if it is old), then starts the tracker threads.
  6. Window. The window opens at 1000 × 640 (minimum 820 × 520). The app loads the Runs list, the card names (on their own thread), the card art index and the saved odds.

Because the lock name comes from the data folder, a debug build and a release build with different folders can run at the same time. With the same folder, only one runs.

6.5 Background threads

ThreadJob
tracker-logFollows Player.log. It sees when the game makes a new file or makes the file shorter.
tracker-gameAttaches to the game, and attaches again after the game restarts.
tracker-connectionReports attach and detach.
tracker-machineRuns the run state machine and saves its Events in order. If a save fails, it tries again after 1 s, then 2 s, up to 30 s. It never drops an Event.
tracker-bridgeMoves each Notice to the window, so the window never waits on the tracker.
card-catalogLoads the card names from the game's GameData.db.
single-instanceWaits for a second copy of the app to ask for the window.

While the game is attached, the tracker reads the live Board about once a second. It sends a LiveSnapshot notice only when the Board changes.

7. How the app stores data

The app keeps all its own data in one folder: the data folder. To move, back up or remove your data, you only need this folder.

7.3 settings.toml

If the file is missing, the app writes it with the defaults. Each key has a default, so a file with only some keys is correct. The app ignores keys that it does not know.

theme = "Rosé Pine"
log_path = ""            # Player.log, if it is not in the usual place
game_dir = ""            # the game's install folder, for card art; empty = find it in Steam
run_sync = false         # upload to Bazaar DB; keep this off
show_run_duration = false
card_size = "medium"     # small, medium or large

[window]
sidebar_open = true
sidebar_width = 248      # 220–520
detail_width = 560       # 240–1200
snapshot_open = true
stash_open = true
odds_open = true
log_open = false
log_details_open = true
log_width = 420          # 260–900
  • When you change a setting in the app, the app saves the file at once. It writes settings.toml.tmp first and then puts it in place of the old file, so a crash cannot leave half a file.
  • If you type a width that is out of range, the app moves it to the nearest limit.
  • If the app cannot read the file, it uses the defaults and does not touch the file until you change a setting.

All keys are in gpui app.

7.4 history.db

history.db is one SQLite file. It holds:

  • each Run and a summary of it (start and end time, hero, day, wins, losses, outcome);
  • each Event of each Run, with its details (and its Snapshot, if it has one) as JSON;
  • the Shop odds and item odds read or imported from Bazaar DB;
  • the items you track, hide or pin.

How the app uses the file:

  • WAL mode. The app has one connection that writes and one that only reads. A read, such as the Runs list, does not wait for a write, such as a new Event.
  • Events update their Run. When the tracker saves an Event, the same write updates its Run's summary.
  • Deleting a Run also deletes its Events. You cannot delete the Live run.
  • Schema updates. If the file is older than the app, the app first copies it to history.v<N>.bak.db, then updates it. The app never deletes that copy. If the file is newer than the app, the app does not open it and shows an error.
  • Times are Unix milliseconds.
CautionOnly one program must write to history.db at a time. The app, just tracker track, and a debug and a release build that use the same folder all write to the same file. Run one of them at a time.

To look at the data, open the file read-only with sqlite3:

sqlite3 -readonly .bazaar-tracker\history.db ".tables"

Every table and column is in history.db and Database schema.

7.5 logs/tracker.log

The app writes info, warnings and errors to logs/tracker.log. Each start adds to the end of the file. When the file gets to 1 MiB, the app renames it to tracker.log.1 and starts a new one. It keeps three old files and deletes the oldest. The times in this file are UTC.

The log panel shows the same rows, plus short sentences about what the tracker saw.

7.6 art/

The app does not include card art. You extract it from your own install of the game:

  • in the app: Settings → Card art → Extract art, or Extract card art in the menu;
  • in a terminal: just tracker art, or just tracker art --game "H:\SteamLibrary\steamapps\common\The Bazaar" if the app cannot find the game.

The first run takes about 30 s and writes about 65 MB of WebP images. Later runs write only the missing images, so run it again after a game patch. --force draws every image again.

CautionThe art belongs to Tempo Storm. It is for your own use on your computer. Do not commit it or share it.

The folder layout is in Data folder.

7.8 Move, back up or clear the data

To back up your data:

  1. Close the app. Make sure that just tracker track does not run.
  2. Copy the whole data folder to a safe place.

Close the app first. While it runs, recent writes can be in history.db-wal and not yet in history.db.

To use a different folder (for example, to test with empty data):

$env:BAZAAR_TRACKER_DATA_DIR = "D:\scratch\tracker-test"
.\target\release\bazaar-tracker-gpui.exe

To set the variable for your user account, see Data folder.

To go back to an older build after a schema update:

  1. Close the app.
  2. Put history.v<N>.bak.db in place of history.db.
  3. Delete history.db-wal and history.db-shm if they are there.

To clear the data from the app:

  1. Open the menu and click Clear data….
  2. Select what to clear: the database (Runs and odds), the card art, or both.
  3. Type delete, then press Enter or click Clear.
CautionYou cannot undo Clear data. Make a backup first if you want to keep your Runs.

8. Check the tracker against the game

These commands need The Bazaar to run. After each game update, run just tracker spike first. Memory reading depends on the game's Unity version and class layout, and an update can change them.

CommandWhat it does
just tracker spikeAttaches and prints the Unity version, the offset table, the loaded assemblies, the fields of the game classes that the tracker reads, the BoardManager singleton and the entity count.
just tracker snapshotPrints one Snapshot: run id, hero, run state, stats, Board, Stash, skills, opponent, rank and last combat. Add -- --watch to print one at each poll.
just tracker trackRuns the full tracker with no window. It saves to history.db and prints each Event. Add -- --log <path> to follow a different Player.log. Press Ctrl+C to stop it.

Do not run just tracker track while the app runs. Both write to the same history.db.

9. Run the tests

just tracker test                            # cargo test --workspace: every crate
cargo test -p bazaar-tracker             # one crate
cargo test -p bazaar-tracker --tests     # that crate, with the full-log replays

The root Cargo.toml is a virtual workspace, so a plain cargo test at the repo root also tests every crate. No test needs the game: mono::testing gives byte buffers to unityspy-rs, FakeMemory and ManualClock drive the run state machine, and crates/bazaar-tracker/tests/ replays the recorded logs in tests/fixtures/logs/. Tests are next to the code, in files named <name>_tests.rs.

10. Troubleshooting

ProblemPossible causeWhat to do
The status bar does not show Tracking.The game is not running, or a game update changed the Unity version.Start the game. Run just tracker spike. If it says no Mono offsets for Unity version …, the offset table for that version is missing. The tables are in crates/unityspy-rs/src/mono/offsets.rs.
The app tracks, but no Events show.The app follows the wrong Player.log.Look at the path in the log panel's pinned details. If it is wrong, set log_path in settings.toml.
Cards have no names or no art.The app did not find the game folder, or you did not extract the art.Set game_dir in settings.toml, then run Extract art or just tracker art --game "<folder>".
history.db has schema version N, but this app only understands up to MA newer build updated the file.Use the newer build. Or use the backup (see 7.8), or point this build at a different folder.
Could not open history.dbThe file is locked, damaged, or is not a file.Close other copies and just tracker track. Look at logs/tracker.log for the reason.
A second start does nothing.A copy of the app already uses this data folder.This is correct. Look for the first window; it comes to the front.
The window lags in a debug build.The dependencies are not optimised.Make sure that [profile.dev.package."*"] with opt-level = 2 is in the root Cargo.toml. Or use just tracker build and just tracker start.
Odds do not load.The WebView2 Runtime is missing, or the Cloudflare check did not pass.Click 🌐 in the status bar to open the Bazaar DB panel. It shows the page and the replies that it got.
