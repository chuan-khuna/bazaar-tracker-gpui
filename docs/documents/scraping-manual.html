Scraping manual

How to save data from Bazaar DB (bazaardb.gg) with the scrapers in app/scraper/, on macOS or Windows: setting up, starting a browser, scraping players' runs and item odds, what you get, and what to do when something goes wrong. The last section explains how it works.

Commands for

1. What you can scrape

Runs

Every run of a player (from their profile), or the top runs of a run feed, such as the best Jules runs. Each run has its result and rank, the final board, and its whole timeline: both boards at each moment, every choice and sale, every fight.

just scraper runs → data/scraper/builds/

Item odds

Bazaar DB's odds for an item, per hero and per tier you already own, for many items at once. They import into the app.

just scraper scrape → data/scraper/odds/

The scrapers only read from Bazaar DB; nothing is ever sent to it. They ask one page at a time, with a random 1–4 s wait in between, at a pace a person could keep.

2. One-time setup

You need uv and just (the repo's mise.toml pins them), and a Chromium browser: Google Chrome, Microsoft Edge, Brave, or Dia on macOS.

macOS 
brew install mise          # or: curl https://mise.run | sh
cd bazaar-tracker-gpui
mise install               # installs uv and just (and the rest of mise.toml)
just scraper sync          # the scraper's Python dependencies, into app/scraper/.venv
Windows (PowerShell) 
winget install jdx.mise    # or: winget install astral-sh.uv Casey.Just
cd D:\code\bazaar-tracker-gpui
mise install
just scraper sync

Run just scraper on its own to list every recipe.

3. Start the browser

Bazaar DB is behind Cloudflare, and part of its data only reaches a real browser. The dependable way is to start your own browser with a debugging port (9222); the scrapers then open a tab in it and use its Cloudflare clearance.

The easy way

just scraper browser            # the first one found: Dia on macOS, else Chrome, Edge, Brave
just scraper browser edge       # that one: dia, chrome, edge or brave
just scraper browser --print    # only print the commands for this machine

It starts the browser, waits until the port answers, and opens bazaardb.gg/run. Pass any Cloudflare check in that window once. You can also skip this step: when nothing answers on the port, both scrapers show these commands and offer to start a browser for you.

By hand

macOS 
# Dia (quit it first)
/Applications/Dia.app/Contents/MacOS/Dia --remote-debugging-port=9222

# Chrome, from the repo root
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9222 --user-data-dir="$PWD/app/scraper/.browser-profile"

# check the port
curl -s http://localhost:9222/json/version
Windows (PowerShell, from the repo root) 
# Chrome
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 --user-data-dir="$PWD\app\scraper\.browser-profile"

# Edge
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9222 --user-data-dir="$PWD\app\scraper\.browser-profile-edge"

# check the port (curl.exe, not PowerShell's curl alias)
curl.exe -s http://localhost:9222/json/version

An answer names the browser ("Browser": "Chrome/…"). No answer: the browser was already running when the flag was given (quit it and start again), or Chrome was started on its default profile.

Quit it when you are done. While the port is open, any program on the machine can drive that browser, with every logged-in session in it. Quit it and start it normally afterwards.

4. Scrape runs

Have the link of a player's profile (https://bazaardb.gg/run/profile/<id>) or of a run feed: open bazaardb.gg/run, set the filters (hero, sort by wins, tracker only…) and copy the address, such as https://bazaardb.gg/run?by=wins&heroes=Jules&tracker=1.

Asked, step by step

  1. From the repo root, run just scraper runs with no arguments.
  2. Tick any profile or feed you scraped before (space to tick, enter when done), then paste new links, one or more per line, and press enter on an empty line to finish. Pasting here means a feed link's ? and & need no shell quoting.
  3. For a feed, say how many runs to take from its top (100 by default).
  4. Say whether to read only runs not saved yet (the usual answer).
  5. Pick the browser. If one answers on port 9222 it is used without asking; otherwise pick one to start, check again after starting one yourself, or let the scraper launch Chrome with its own profile. Profiles need a browser only past their first 20 runs; feeds always need one.
  6. For each profile or feed you see how many runs there are and choose Start, Show every run first, Skip this one or Cancel the rest.

5. Scrape item odds

The odds scraper needs the tracker's item list, items.json, which the app writes when it loads the card catalog.

Windows

Run the app once (just app run); it writes .bazaar-tracker/items.json, which the scraper finds by itself.

macOS

The app runs on Windows only, so copy .bazaar-tracker/items.json from a Windows machine and pass it: just scraper scrape --items ~/Downloads/items.json. Scraping on macOS is also how to get item odds there.

  1. Run just scraper scrape with no arguments.
  2. Pick the browser, as for runs (asked only when nothing answers on the port).
  3. Tick the characters; each shows its item count.
  4. Say whether to ask only for items not scraped yet, whether to retry the skipped list (if there is one), and how many retries per failed item.
  5. Check the table of what will be asked and choose Start, Show every item first or Cancel.

A whole hero with its neutral items is about 380 items and up to four asks each, so expect an hour or more. With arguments it runs straight away, for example just scraper scrape --hero Jules --no-neutral --limit 20. Every option is in Odds scraper.

Import into the app (Windows)

In the app, open the ☰ menu or the command palette (Ctrl+P), run Import item odds… and pick the data/scraper/odds/ folder. Only newer odds replace saved ones, so importing twice changes nothing.

6. What you get

Everything goes to data/scraper/ at the repo root, which git ignores.

data/scraper/
├── builds/                          # runs
│   ├── <profile id>/
│   │   ├── metadata.json            # the player: id, name, run count
│   │   ├── stats.json               # their stats and card checklist (profiles scraped directly)
│   │   ├── index.json               # every saved run: season, hero, wins, rank, rating, file
│   │   └── runs/season-20/<run id>.json
│   └── feeds/<filters>.json        # a feed's runs in its order, e.g. by-wins_heroes-Jules_tracker-1.json
└── odds/                            # item odds
    ├── <template_id>.json           # one item: odds per hero and owned tier
    ├── index.json
    └── skipped.json                 # asks that got no odds, to retry

A run file holds summary (result, rank before and after, final items and skills, one entry per fight) and timeline (snapshots of both boards, events for each choice and sale, combats with the opponent, monsterNames). Card art is left out. Runs are filed by the season they were played in. Every file is plain JSON with a format number.

7. Stopping, carrying on, Cloudflare

  • Ctrl+C stops at any time. Run the same command again to carry on: what is saved is left out. Files are written whole or not at all.
  • Esc or Ctrl+C on a question stops before anything is read.
  • A Cloudflare check in the browser window: do it there; the scraper waits up to 5 minutes (--human-wait) and carries on. If it is not passed, the scrape stops with a message; run it again.
  • Leave the scraper's tab alone while it works. When attached, only its own tab is closed at the end.

9. How it works

Bazaar DB is a Next.js site, and its data comes two ways:

In the page

Each page carries the data it was built from (its React Server Components "flight" payload): a profile with its newest 20 runs, a run's whole timeline. A plain HTTP request gets it.

From /api/*

Item odds, a profile's runs past the 20th, and run feeds. The API wants a Cloudflare Turnstile token that only a real browser earns.

  • The run scraper fetches pages over plain HTTP and reads the flight payload out of them: it joins the self.__next_f.push(…) pieces, splits them into rows, follows the $ references between rows, and finds the props by their keys (initialRuns and profile; snapshots, events and combats). It opens a browser only for a feed, a profile with more than 20 runs, or when Cloudflare stops it, and from then on uses the browser. In the browser it scrolls the run list and keeps the /api/run replies the page gets, 20 runs a page.
  • The odds scraper works only in the browser, as a person would: on shop-odds?hero=… it types the item into the page's search, picks the exact match, clicks each "Currently owned tier" button, and keeps the /api/item-odds replies the page gets. It never makes an API request itself.
  • Seasons: a run has no season of its own, so it is filed by when it was saved, against the season starts in the site's script (with a built-in list if the script cannot be read).
  • Browsers: start-browser looks for Dia, Chrome, Edge and Brave in the usual install folders (/Applications and ~/Applications on macOS; Program Files and Local AppData on Windows), starts one apart from the scraper so it keeps running, and waits for /json/version to answer.

The details are in Scrapers (the principles and the run scraper in full) and Odds scraper (every odds option and the import).
