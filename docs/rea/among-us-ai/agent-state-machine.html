25 พฤศจิกายน 2026 · สรุปจากโค้ดใน references/among-us-ai (commit 76c23d7) · ไฟล์หลัก src/agents/prompts.js, src/agents/agent.js, src/engine/game.js, src/match/runner.js, src/bridge/runner.js · prompt ที่ยกมาเป็นภาษาอังกฤษตามต้นฉบับ (ตัดย่อบางส่วน) · คำที่ขีดเส้นประ ชี้เพื่อดูความหมาย

สรุปสั้น ๆ

among-us-ai ไม่ได้ให้ LLM บังคับตัวละครทีละเฟรม และไม่ได้ให้ LLM อ่าน state ดิบของเกม วิธีที่ใช้คือ

  1. แยก Brain กับ Body LLM (brain) สั่ง order ระดับสูง เช่น move:Admin, kill:Kimi แล้ว body (simulator หรือเกมจริงผ่าน mod) ทำ order นั้นต่อไปเองหลายวินาที ทั้งเดิน, หาทาง และทำ task
  2. ปลุก brain เฉพาะที่ decision point คือ order เดิมเสร็จ หรือมีเหตุการณ์มาขัด เช่น เจอศพ, เห็นการฆ่า, มี sabotage, มีคนพูดใส่ หรือ (impostor) อยู่ตามลำพังกับ crewmate และ kill พร้อม เหตุที่ปลุกถูกเขียนลง prompt ด้วย (You are deciding now because …)
  3. แปลง state เป็นข้อความที่ผู้เล่นคนนั้นรู้ได้เท่านั้น คือ View (ตอนนี้เห็นอะไร) กับ Episodic memory (log ส่วนตัวที่ engine เขียนจากสิ่งที่เห็น) ไม่มีวันได้ state ของคนอื่น
  4. ให้เลือกจาก legal actions prompt แนบรายการ action id ที่ทำได้ ณ ตอนนั้น พร้อม label ที่บอกระยะทางและเวลา โมเดลต้อง copy id มาตอบ ถ้าไม่ตรงจะ fuzzy match และถ้ายังไม่ได้ก็ตกเป็น wait:5
  5. ตอบเป็น JSON ที่บังคับ schema ตาม state แต่ละ state มี schema ของตัวเอง (roam, speak, vote, reflect) และทุก schema มีสองเสียง: to_camera (ความคิดจริง ไม่มีผู้เล่นคนอื่นเห็น) กับส่วน public
  6. หยุดเวลาระหว่างโมเดลคิด ใน simulator นาฬิกาเกมไม่เดินจนกว่าทุก brain จะตอบ ในเกมจริงจะ pause ทุก copy ของเกม (Time.timeScale = 0) โมเดลที่ช้าจึงไม่เสียเปรียบ

State machine ระดับ match

ตัว engine มี phase แค่ 3 ค่า: roam, meeting, over แต่ runner แบ่ง meeting ออกเป็นช่วงพูดกับช่วงโหวต และหลังจบเกมมีช่วง reflect แต่ละ state ใช้ prompt และ schema คนละแบบ (ดูตารางใต้แผนภาพ)

  state Roam {
    [*] --> Acting
    Acting --> Deciding: decision point
    Deciding --> Acting: act(order)
  }
  Roam --> Speaking: report / emergency
  state Meeting {

    Speaking --> Voting: ครบ discussionRounds

  Voting --> Roam: endMeeting()
ทุกคน needs = meeting_over
  Roam --> Over: checkWin()
  Voting --> Over: เกมจริง: จบที่ผลโหวตได้
  Over --> Reflect: persistentMemory
  Reflect --> [*]
  Over --> [*]
Stateเข้าเมื่อใครถูกถามPrompt / schemaออกเมื่อ
Roam · Decidingมีคน needs ไม่เป็น nullทุกคนที่ needs พร้อมกัน (parallel)roamPrompt · roamได้ action แล้วส่ง act()
Roam · Actingรับ order แล้วไม่มีใคร: body ทำเองไม่มีorder เสร็จ (idle) หรือเหตุการณ์ interrupt
Meeting · Speakingreport หรือ emergencyทีละคน เริ่มจากคนเรียก วนตามที่นั่งspeakPrompt · speakครบ discussionRounds รอบ
Meeting · Votingจบการพูดทุกคนที่ยังมีชีวิต พร้อมกันvotePrompt · voteนับคะแนน, เขียนบันทึก meeting ลง memory ทุกคน
Reflectเกมจบและเปิด persistentMemoryทุก seat พร้อมกันreflectPrompt · reflectเขียน lesson ลง memory/<seat>.md

State machine ของ seat หนึ่งคนระหว่าง Roam

นี่คือหัวใจของวิธีนี้ seat หนึ่งคนอยู่ใน Acting เกือบตลอด (body ทำ order) และถูกดึงไป Deciding เมื่อ engine ตั้ง p.needs = <reason> เท่านั้น reason แต่ละค่ากลายเป็นประโยค "You are deciding now because …" ใน prompt

State กลายเป็น prompt อย่างไร

ทุก model call ประกอบด้วยสองส่วน: system prompt ที่คงที่ทั้ง match และ user prompt ที่สร้างใหม่ตาม state

คงที่ทั้ง match (cache ได้) สร้างใหม่ทุกครั้งตาม state output ที่บังคับด้วย schema

System prompt (ทุก state ใช้ร่วมกัน)

สร้างครั้งเดียวต่อ seat ใน systemPrompt() และเหมือนเดิมทุก byte ตลอด match เพื่อให้ provider cache ได้ เนื้อหาเรียงตามนี้

1
ตัวตน: You are <name>, a player in AMONG AI … every player is a different AI model. Play to win and stay in character.
2
PLAYERS: รายชื่อ สี (และชื่อโมเดลถ้าเปิด revealModels) พร้อม <- you
3
YOUR SECRET ROLE: IMPOSTOR (พร้อมชื่อคู่หู, วิธีชนะ, "Kill when nobody is watching, use vents, sabotage, pretend to do tasks… lie at meetings") หรือ CREWMATE ("Do your tasks, watch who goes where, and catch the liars")
4
HOW THE SHIP WORKS: เวลาเป็น [mm:ss], รู้แค่สิ่งที่ตัวเองเห็น, กฎ vision, visual task พิสูจน์ว่าเป็น crew, กฎการพูดนอก meeting ("Stay silent most of the time… Do not narrate your own route"), report / emergency, คนตายพูดไม่ได้
เวอร์ชันเกมจริงบอกเพิ่มว่า "it keeps running while you think: decide fast" และ vision คือสิ่งที่อยู่บนจอ
5
TWO VOICES: ทุก reply มี to_camera (confessional แบบ reality show 1–3 ประโยค) กับส่วน public, ความยาวของ say (≤ 100 ตัว) และสไตล์ของ chat_message (สั้น อารมณ์ แสลง ไม่มี list/markdown ห้ามขึ้นต้นซ้ำกับ 3 ข้อความล่าสุด)
6
ALIBI DISCIPLINE: คำอ้างว่าอยู่ไหน เห็นใคร ต้องมาจาก memory log, ห้ามพูดเวลา 00:13 ออกมา ให้พูดแบบคน ("just now", "before the lights went out"), ถ้าโกหกให้วางแผนใน to_camera และพูดให้คงเส้นคงวา
7
LANGUAGE: ภาษาที่ใช้คิดและพูด (ไทยมีตัวอย่างประโยคและห้ามพูดถึง "เกม")
8
YOUR PERSONALITY (ถ้ามี persona) และ YOUR MEMORY FROM PAST MATCHES: lesson จาก match ก่อน ๆ สูงสุด 8 บรรทัด
9
Reply with one JSON object only, with exactly the fields you are asked for.
ชื่อ field ความคิดคือ to_camera ไม่ใช่ secret_thought หรือ reasoning เพราะโมเดล Claude ปฏิเสธ turn ที่ schema ขอ "thoughts" หรือ "reasoning" (Opus ปฏิเสธทุก turn ของ match หนึ่ง) จึงเปลี่ยนเป็น confessional ของ reality show แทน ฝั่ง parser ยังรับชื่อเก่าเป็น alias

View: ภาพ ณ ตอนนี้

game.view(id) คืนเฉพาะสิ่งที่ผู้เล่นคนนั้นรู้ได้: เวลา, role, ตำแหน่ง, กำลังเดินไหม, reason, คนที่มองเห็น (ชื่อ, อยู่ไหน, ทำอะไร: walking to X / doing a task / fixing lights / standing), จำนวนเงาในที่มืด, ศพในห้อง, sabotage กับเวลาที่เหลือ, tasks ของตัวเอง, task bar ของ crew, (impostor) คู่หู, kill/sabotage cooldown, vent ที่ไปได้, คนที่ทุกคนรู้ว่าตายแล้ว และ legal

Legal actions สร้างจาก state ตอนนั้น แต่ละตัวมี id ให้ copy และ label ให้เข้าใจ โดย label ใส่ข้อมูลที่ต้องใช้ตัดสินใจไว้แล้ว เช่น เวลาเดิน

- wait:5  (stay where you are for 5s)
- move:Electrical  (walk to Electrical (~9s))
- task:wires  (do Fix Wiring @ Electrical (~9s away, takes 4s))
- task:scan  (do Submit Scan @ MedBay (~6s away, takes 10s, visual task))
- follow:GPT  (follow GPT for up to 20s)
- report  (report the body of Kimi)
- emergency  (walk to the Cafeteria button and call a meeting (~12s, 1 left))
- fix  (fix lights @ Electrical (~9s))
# impostor เท่านั้น
- kill:Kimi  (kill Kimi right now)            ← มีเฉพาะเมื่อ cooldown 0 และอยู่ห้องเดียวกัน
- vent:Navigation  (vent to Navigation (instant; anyone watching sees it))
- sabotage:reactor  (sabotage reactor (crew must fix it within 40s or you win))
- fake:scan  (pretend to do Submit Scan @ MedBay …)

ตัวอย่างประกอบ ชื่อและเวลาสมมุติ แต่รูปแบบตรงกับ legalActions() ใน game.js

renderLog(limit) ส่ง N บรรทัดล่าสุดแบบเต็ม (roam 25, meeting 60) บรรทัดที่เก่ากว่าและเป็นเรื่องปกติจะย่อเป็น route ส่วน evidence (ศพ, การฆ่า, vent, visual task, sabotage, สิ่งที่ได้ยินและสิ่งที่ตัวเองพูด, ผลประชุม) ไม่ถูกตัดทิ้ง นอกจากนี้ memory ยังเก็บ note ที่โมเดลจดเอง (12 ล่าสุด), to_camera ของตัวเองในอดีต และบันทึก public ของทุก meeting

Body รับ order ไปทำต่อ: move เดินตามทางสั้นสุด, task/fake เดินไปแล้วทำ, follow ตามได้ไม่เกิน 20 s, emergency เดินไปกดปุ่ม, report เปิด meeting ทันที, kill/vent/sabotage ทำทันทีแล้วรอ 1 s ถ้า order ใหม่เป็นงานเดียวกับที่ทำอยู่ (ถูกปลุกกลางงานแล้วสั่งงานเดิม) จะทำต่อจากเดิม ไม่เริ่มใหม่

สิ่งที่นำมาใช้กับ Advisor ได้

ตอนนี้ Advisor ของเราทำงานเมื่อผู้เล่นถามเท่านั้น ถ้าจะให้มันตัดสินใจหรือเสนอเองตาม stage ของเกม รูปแบบจาก among-us-ai ที่เข้ากันได้คือ

  • reason ที่ปลุก เช่น "เพิ่งเปิด Offer", "เข้า Hour ใหม่", "จบ combat" แล้วใส่ไว้ในบรรทัดแรกของ prompt แบบ You are deciding now because …
  • legal actions พร้อม label ให้เลือก id จากตัวเลือกใน Offer พร้อมราคาและขนาด แทนที่จะให้โมเดลพิมพ์ชื่อการ์ดเอง แล้ว fuzzy match / fallback แบบ matchAction()
  • schema ต่อ state ตัวเลือกร้าน, การจัด Board และการเลือก skill ใช้ schema คนละแบบ แทนที่จะใช้ schema เดียวสำหรับทุกอย่าง
  • system prompt คงที่ + user prompt ตาม state ซึ่ง Advisor ทำอยู่แล้ว (situation อยู่เหนือคำถาม ไม่อยู่ใน system prompt)
  • lesson หลังจบ run ให้โมเดลเขียนโน้ตถึงตัวเองใน run หน้าแบบ reflectPrompt

Glossary

คำของโดเมน (GLOSSARY.md)

Advisor
agent ที่ผู้เล่นถามเรื่อง build ได้: เลือกไอเทมไหน, อะไรเข้ากัน, ไปร้านไหน, จัด Board อย่างไร, เลือก skill ไหน ตอบจาก card catalog, odds และ runs ที่ scrape มาจาก Bazaar DB

คำของ among-us-ai

Brain
Agent ที่ตัดสินใจแทน seat หนึ่ง: memory, prompts และ provider (โมเดล) ของมัน
Body
สิ่งที่ทำตาม order ของ brain: engine ของ simulator หรือ Among Us หนึ่ง copy ในเกมจริง
Order
action ระดับสูงที่ body ทำต่อเองในหลายวินาทีถัดไป: move, task, follow, kill, vent, sabotage, fix, report, emergency, wait
Decision point
จังหวะที่ brain ถูกถาม: match เริ่ม, order เสร็จ, meeting จบ หรือมีเหตุการณ์ขัด (ศพ, การฆ่า, sabotage, มีคนพูดใส่, โอกาสฆ่า) ไม่ได้ถามทุกวินาที
View
สิ่งที่ seat หนึ่งรู้ได้ ณ ตอนนี้: game.view(id) ใน simulator หรือ state ของ copy ตัวเองในเกมจริง ไม่มีวันเป็นของ seat อื่น
Legal actions
order ที่ seat สั่งได้ตอนนี้ แต่ละตัวมี id เช่น move:Admin หรือ kill:Kimi และ label อธิบาย
Observation obs
บรรทัดเดียวที่ engine เขียนลง memory ของผู้เล่นคนหนึ่งเกี่ยวกับสิ่งที่เห็น: เข้าห้อง, ออกไปทางไหน, เจอศพ, เห็นการฆ่า
Episodic memory
log ส่วนตัวมีเวลากำกับของ seat หนึ่ง: observation, note, to_camera ในอดีต และบันทึก public ของ meeting
Freeze
เวลาเกมหยุดเดินขณะที่มี brain ใดกำลังคิด โมเดลที่ช้าจึงไม่เสียเวลาในเกม
