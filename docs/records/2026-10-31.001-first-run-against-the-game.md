# First run against the game: `just spike` and `just snapshot`

## What was discussed

This was the first time `unityspy-rs` and the game layer were run against the live game: The Bazaar, pid 11776, exe version 6000.3.11.239, so Unity 6000.3.11. `just spike` (tickets 06–08) ran at the main menu. `just snapshot -- --watch` (ticket 11) then ran through an Unranked run as Jules: a shop, a PvE combat and a PvP fight against `capJASP` (Mak). The raw output of both commands is at the end.

## What worked

- **Attaching (06).** `mono-2.0-bdwgc.dll` and the root domain were found. 214 assemblies were listed, including `mscorlib`, `UnityEngine.CoreModule`, `TheBazaarRuntime`, `BazaarGameClient`, `BazaarGameShared` and `BazaarBattleService`.
- **Unity 6 offsets.** The table copied from 2021/2022 held for the domain, the assembly list, the class cache, the class model, fields, statics and object reads. It is still marked unverified, because the generic-instance offsets had not been exercised yet (see below).
- **Classes and fields (07).** All four classes were found. Every top-level field path in `memory-reading.md` §2 exists with a plausible type code. `ClientCache.RunConfig` is CLASS (0x12) rather than GENERICINST, so it is a non-generic subclass of `Observable<T>`.
- **Snapshot reads (11):**
  - Run init: run id, play mode `Unranked`, build `12979`, environment `Production`.
  - Selected hero: `Jules`.
  - Rank: rating 500, Diamond, division 1.
  - PvP opponent: `capJASP` (Mak), rating 500, level 2.
  - Last combat: winner and loser, which flipped from 0/1 to 1/0 between the two fights.

## What failed

- **At the main menu (08).** `BoardManager.Instance` was "not initialised" and `Data.Entities` had 0 entries. No `BoardManager` exists outside a run, so this is expected, not a bug.
- **Every board read (11).** Each failed with `field 'key' of 'System.Collections.Generic.Dictionary`2+Entry' has a generic parameter type, not a concrete one`.
  - The cause: array elements and `GENERICINST` struct fields were read through `MonoGenericClass.container_class`, the generic definition. The definition's fields are `VAR` and have no real offsets.
  - Five failures in a row make the tracker detach, which is why the output shows a detach and reattach roughly every five polls.

## Decided

- **The board-read fix.** `GENERICINST` now resolves to `MonoGenericClass.cached_class`, the instantiated class. It is at 0x20, per Mono's `class-internals.h`, and is trusted only when it points back at the same generic class; otherwise the reader falls back to the definition. Struct array elements are read with the array's own element class.
  - Two tests model the real layout: a `VAR` definition, a concrete instance and the `MonoGenericClass` joining them.
  - The workspace tests pass. The fix is uncommitted at the time of writing.
- **Tickets.** 06 and 07 are resolved. 08 stays `ready-for-human` until `just spike` is rerun in a run.

## Open questions

- Does the fix work on the game? Rerun `just snapshot -- --watch` in a shop and compare the board with the screen. Then rerun `just spike` in a run to check `BoardManager.Instance` and the `Entities` count.
- Is `frame_count` right? Both combats report 665 frames, a PvE win and a PvP loss. Two different fights with the same count is suspicious: the reader may be getting a stale or wrong `Frames` list, or a capacity instead of `_size`.
- Does attaching need admin rights? It worked here, but this run did not record whether the shell was elevated.
