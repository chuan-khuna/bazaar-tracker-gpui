# `just spike` during a run

## What was discussed

`just spike` was rerun during the same Unranked run as Jules, in the shop recorded in `2026-10-31.002-board-reads-after-the-generic-fix.md`. The first spike, at the main menu (record `.001`), could not check ticket 08's values because no run was active.

## Results

- **Assemblies and classes.** These match record `.001`, except for one new assembly, `System.Xml.Linq`, loaded since then. The field offsets of all four classes are unchanged.
- **`BoardManager`.** It now reports `initialised`, and `BoardManager.Instance` resolves through the `Singleton<BoardManager>` base class to `BoardManager at 0x217136e7000`. That confirms static reads through an inflated generic class.
- **`TheBazaar.Data.Entities`.** It has 12 entries. The snapshot on the same screen counted 10 cards:
  - 4 board items and 1 socket effect
  - 1 stash item
  - 1 skill
  - 3 shop offers

  The other 2 are entities the snapshot does not bucket. They are most likely the merchant's encounter card and its step. That is plausible, but nobody counted them on screen.

## Decided

- Ticket 08 is resolved: statics, objects, the singleton through its base class and `Dictionary` counts all read correctly on the real game.
- The Unity 6 offset table can be treated as verified for everything the tracker reads so far. That covers the domain, classes, fields, statics, objects, strings, arrays, generic instances, and the `List`, `Dictionary` and `HashSet` readers. Flipping `verified` to `true` in `offsets.rs` waits until combat reads (ticket 11) are checked too.
