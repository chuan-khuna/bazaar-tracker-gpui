# `src/` grouped by feature inside its layers

## What was discussed

`src/tracking/` had grown to 18 flat files mixing three concerns: the selected Run's view models, the link to the tracker service, and the log panel. `src/ui/` mixed the Run's sections with the window's frame in the same way. Three files were named `settings.rs` (`shell/`, `overlays/`, `ui/`).

Two layouts were weighed:

- Keep the layers of `2026-10-31-folder-structure-and-ui.md` (`tracking/` with no drawing, `ui/` drawing it) and group by feature inside each.
- Feature folders holding both halves, such as `features/run/board/{model.rs, view.rs}`.

## Decided

- The layers stay, so the view models are still tested without a window. Inside them, files are grouped by feature, with the same folder names on both sides:
  - `tracking/run/` and `ui/run/`: the selected Run (header, moment, board, economy, events, detail, and the main panel on the UI side).
  - `tracking/log/` (details, feed, narrate, and `rows.rs`, formerly `log.rs`): what the log panel shows. `ui/log_panel.rs` draws it.
  - `ui/frame/`: the window itself (title bar, menu, palette, theme picker, settings overlay, sidebar, status bar).
  - Shared code stays at the top of `tracking/`: service, status, session, names, when.
- `live.rs` stays at the top of `tracking/` and `ui/`: a folder holding only `live/live.rs` would trip clippy's `module_inception`.
- The settings overlay's files are `settings_overlay.rs` in `overlays/` and `ui/frame/`; `shell/settings.rs` is the only `settings.rs`.
- `shell/` is unchanged.
- Drawing methods in `ui/frame/` and `ui/run/` are `pub(in crate::ui)`, so `ui/mod.rs` and sibling folders can call them.

## Open questions
