# Remove the upload feature; Runs are saved to the local history.db only

## What was discussed

While writing `docs/documents/upload.md`, it came up that the tracker has an upload feature,
ported from the original BazaarDBTracker, that sends saved Events to Bazaar DB.

What it is today:

- `crates/bazaar-tracker/src/upload/` (`uploader`, `batch`, `transport`, `secret`) is built and
  tested, but nothing in the app starts an `Uploader`. Its tests post to a fake server on
  127.0.0.1.
- `run_sync` in `settings.toml` defaults to `false`, and nothing reads it.
- The secret key would be kept in the Windows Credential Manager (`keyring`, service
  `BazaarTracker` or `bazaar-tracker-dev`).
- `events.upload_status` (migration 2: 0 waiting, 1 sent, 3 rejected) records upload state.

So nothing leaves the machine now. The player does not want the feature at all.

## Decided

- Run data is saved to the player's own `history.db` only. The tracker never sends Runs or Events
  anywhere.
- The upload feature is to be removed, not just left off.
- Reading Bazaar DB's Shop odds and item odds stays. It only fetches data and sends no Run data.
