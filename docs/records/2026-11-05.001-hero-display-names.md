# Hero display names

Follows [`Hero8` is not a hero name](2026-11-02.002-hero8-is-not-a-hero-name.md).

## What was discussed

How to show `Hero8` under a name a player knows. The proposal was a mapping, hard-coded in the code, from the game's name to the display name, such as `{ in_game: "Hero8", display: "The Dragons" }`, and a warning in the Settings panel when a hero name appears that the mapping does not have, so the list gets updated.

## Decided

- **A built-in table, listing every hero.** `hero_names::NAMES` in `crates/bazaar-tracker/src/enums/mod.rs`, next to the `EHero` enum, maps each game name to its display name: `Pygmalien`, `Vanessa`, `Stelle`, `Jules`, `Dooley`, `Mak` and `Karnok` map to themselves, and `Hero8` maps to `The Dragons`. Because every hero is listed, a name missing from the table means a new hero; a table with only the odd ones could not tell. `Common` (the neutral items) is not a hero and is not listed, but it counts as known.
- **The game's name stays the key.** Nothing saved or compared changes: `history.db` (`runs.hero`, `item_odds.hero`, the event JSON), `ItemOddsBook` lookups, catalog matching and `?hero=` for Bazaar DB keep `Hero8`. No migration is needed.
- **The display name is used only for what is shown**, through `hero_names::display_name`: the run list, the Run header, the narrated log (run started, PvP opponent), the Events list (`vs …`), the item odds pop-up, the Tracked items text, the Settings hero buttons (the label only, not the key) and the item odds load line in the status bar. The fallback is display name, then the game's name, then the number, which `name_or_raw` already gives for an unknown enum value.
- **Warn about unknown heroes.** Any hero name, from the catalog's `Heroes` or read from memory for the hero being played, that is not in the table shows a note in Settings → Item odds and is logged once as a warning. Nothing breaks: the hero is shown by the game's name.
- **A test guards the enum.** Every name in the `EHero` table must be in `hero_names::NAMES`, so a new enum value without a display name fails the tests.
- **Built in, not in `settings.toml`.** A new hero comes with a game patch, which usually needs a tracker release anyway.

## Open questions

- **"The Dragons" is not checked in the game.** It comes from the skin "Explosive Debut Dragons" and a Mobalytics guide. Read it off the hero select screen and correct the table if it differs.
- **Bazaar DB's name for this hero.** The display table does not fix this. If bazaardb.gg answers `?hero=Hero8` with another name in its `hero` field, `accept()` saves the odds under that name and every lookup by `Hero8` misses. Check with one request before running the bulk load for this hero.
